### D-1 · 冻结的对拍夹具是「行为基准」还是「数据快照」？

**冲突**：`docs/design/calculation-rules.md` §10「行为基准」写着「公式与参照实现冲突时以参照实现的输出为准……
确需变更行为时，先确认是有意改动，再更新期望值，**绝不能反向修改夹具**」。
而按 Wiki 修正冲击力数值 = 修改夹具里的 `calculator-config.js` = 字面上「反向修改夹具」。

**先例**：`docs/design/calculation-rules.md` §6 已经把 `pr_8`（穿透率 +8%）与 `def_pct_16`（防御力 +16%）
记为「**超出参照实现**」的两条 —— 即事实上已经在按「数据快照」处理，只是没写成规则。

**选项**：

| 选项 | 内容 | 代价 |
| --- | --- | --- |
| ① 行为基准 | 冲击力数值也不许改，错值固化 | 与官方永久不一致，且 CI 绿灯掩盖问题 |

### G. 伤害引擎的乘区规格（**现在是主线前置**，不再是可选项）

底层机制系列给出的官方口径可以直接当规格用，避免自己拍脑袋。
A3-选 ③ 之后，下面三条**必做**——它们是「引擎算出来的最优」能被信任的前提。

| 编号 | 优先级 | 内容 |
| --- | --- | --- |
| **G1** | **P1** | **乘区总纲**（以底层机制系列 + 666bj《数据机制导论 2.0 版》交叉校对为准）：常规伤害 = 基础伤害区 × 增伤区 × 暴击区 × 防御区 × 抗性区 × 减易伤区 × 失衡易伤区 × 特殊乘区；贯穿伤害多一个「贯穿增伤区」；异常伤害换成 异常精通区 × 伤害等级区 × 异常增伤区 × 异常暴击区。各乘区的有效范围（增伤区 [0,6]、异常精通区 [0,10]、减易伤区 [0.2,2]、贯穿增伤区 [0.2,9]、异常增伤区 [0,3]、异常掌控区 [0,3] 且向下取整、防御区 (0,1]）应作为硬约束写进规格。**增伤区是加算区**，而**属性增伤 / 贯穿增伤 / 异常增伤 / 直接攻击增伤分属不同乘区，不互相稀释**——这是最容易做错的一处 |
| **G2** | **P1** | **局内 / 局外分离**与**快照 / 实时结算**的分界线：面板值 ≠ 战斗值。局外白值 + 局外绿值 → 进战斗合并成战斗白值（能量自动回复、攻击力、冲击力同构）。异常伤害里，攻击力 / 增伤 / 等级 / 穿透率 / 穿透值 / 异常精通 / 失衡值提升走**积蓄时加权**；抗性 / 减抗 / 减防 / 无视防御与无视抗性 / 失衡易伤 / 异常增伤 / 异常暴击走**结算时实时**；无视防御与无视抗性**不进加权** |
| **G3** | P2 | **失衡公式**（若要算失衡）：累积失衡值 = 冲击力 × 失衡倍率 × 失衡抗性区（弱点 1.2 / 抗性 0.8）× 失衡值提升区 × 受到失衡值提升区；紊乱再乘失衡等级区 `1 + 0.0075 × 等级`（60 级 = 1.45），紊乱失衡倍率恒为 200%。**6 号位冲击力主词条是提升失衡值的渠道之一**，与穿透率 / 穿透值无关 |

**引擎的边界（写进规格，避免滑向完整战斗模拟）**：

| 引擎**做** | 引擎**不做** |
| --- | --- |
| 给定配装 → 算出一个（或一组）伤害值 | 时间轴、能量循环、异常积蓄时长、轴切与配队时序 |
| 在配装空间内搜索最优 | 掉落概率、养成规划、账号与云端存档 |
| 面板行的边际收益（以伤害为口径） | 局内资源与动画帧率 |

## 5. 线三：推导引擎（把「面板参考」从结论变成可复算的推导链）

### 5.0 目标与设计原则

**目标**：毕业面板不再是「一次手填、之后不再看」的结论，而是任何人（或任何代理人）都能
**独立理解、独立复算**的推导链——

```
输入：预设（base / core / 音擎 / 套装）+ 规则表 + 决策参数（buildSpec）
过程：可解释的取舍链（为什么选暴伤而不是暴击率、为什么 30 条而不是 54 条、为什么这把音擎）
输出：面板数值 + 论证表（收益 / 对比 / 等效 / 优先级验证）
复算：一条命令得到同一份结果
```

**面板口径（本项目的既定口径，不可变）**：

> **面板参考 = 0 影画 + 专武的局外面板。**
> 影画一律按 0 计；音擎一律取该代理人的**专武**；不含专武局内加成、不含 4 件套、
> 不含队伍增益、不含属性伤害类 2 件套效果。

**两条内容边界（必须在文档与页面上分清）**：

| 层 | 装什么 | 不装什么 |
| --- | --- | --- |
| **面板层**（`graduationPanel` / `graduationPanelAlt`） | 0 影画 + 专武的**局外面板**数值，以及推导链 | 影画加成、专武局内加成、4 件套、队伍增益、属性伤害 2 件套 |
| **攻略层**（正文 / `cinemaPriority.note` / `weapons[].note` / `teams[]`） | 上述**复杂情况**的说明与推导：影画怎么叠、局内满暴率线怎么来、换音擎差多少、队伍怎么配 | —— |

> **口径固定之后，面板层反而更简单、更好复算**：面板只依赖「代理人预设 + 专武 + 套装 + 主副词条分配」，
> 全部可从 `data/catalog/` 取到；所有跨口径的推导一律下沉到攻略层，用文字说明，
> **不再出现「局外 72.2% → 局内正好 100%」这种跨口径数字同页、局内那半还是手推的情况**。

**五条原则**（与本仓库既有纪律一致）：

| 原则 | 说明 |
| --- | --- |
| **口径固定：0 影画 + 专武** | 面板层只算这一种口径。影画与局内加成不进面板、不进 `buildSpec`；需要时在攻略层用文字补 |
| **决策与事实分离** | 事实（基础面板、核心加成、音擎数值、套装效果、规则表）进 `data/catalog/`；**决策**（选哪把、选哪条、选几个）进策略文件的机器可读字段，不混在同一处 |
| **推导链必须落盘** | 只存结论不算推导。面板要带 `derivation`（为什么这么配），人能复核 |
| **口径必须声明** | 每个面板都要写明它**是**什么口径（0 影画 + 专武 / 满配 / 小毕业），避免不同页面的数字被跨口径比较 |
| **不可推导的必须显式标注** | 4 件套条件触发、属性伤害 2 件套、影画与局内加成——不是「没算」，而是**算不了且必须写清**；其中影画与局内加成**下沉到攻略层** |

### 5.1 先补 4 个 P0 缺口（本计划此前未覆盖）

| 编号 | 缺口 | 证据 | 后果 |
| --- | --- | --- | --- |
| **T1** | **数值闸门只覆盖 1 份**。`calc_graduation_panel.py --check-all`（`:502-542`）**只验形状不验数值**；`tools/agent_audit.py:397-431` 的 `check_generated_freshness()` 只跑**单文件** `--check`（默认叶瞬光） | 面板漂移只有参考实例能发现 | 其余 60 份面板的数值**无任何保证**；`backend/tests/test_strategy_data.py` 也**不断言任何面板数值** |
| **T2** | **`tools/agent_deploy.py:369-372` 只传 `--strategy`** → 全部 build 参数落到脚本的 `BUILD` 默认值（叶瞬光口径，`:114-129`） | 该调用没有 `--agent-id/--weapon-id/--disc4…` | **新代理人的毕业面板会被写成叶瞬光的**（`build.agent` 字段会是「叶瞬光」）。目前现存 61 份里只有叶瞬光自己含该字段，说明这条路径尚未真正跑过——**是潜伏的 bug，不是已爆的 bug** |
| **T3** | **三份「展示名」真源并存** | `calc_graduation_panel.py` 的 `TOTAL_LABELS`（`:173-188`）与 `SUB_STAT_LABELS`（`:136-147`）；`backend/tests/test_strategy_data.py` 的 `MODIFIER_TO_LABEL`（`:406-425`）；`frontend/src/strategy/substats.ts` 的 47+7 口径靠**反解中文串** | 改名要同时改三处，漏一处就错；前端「47+7」是从 `"54 条满配：暴击率 ×12、…"` 反解的，**文案一改就崩** |
| **T4** | **口径没有写死，也没有机器可断言** | 全仓库 grep：`agents.json` 无 `cinema`/`film`/`passive`/`skill` 键；`backend/src/zzz_panel/core/` 零命中。影画的局内加成（如 +8% 暴击率）只存在于 `cinemaPriority.note` 文案。**更关键：`data/catalog/weapons.json` 只有 `roleTag`，没有「代理人 ↔ 专武」的映射**，「用的是不是专武」目前只能靠人肉看策略 JSON 里 `weapons[].tier == 首选` 的名字 | 口径虽然事实上已经是「0 影画 + 专武」，但**既没写在文档里，也没法被断言**——于是「用错音擎」「偷偷把影画算进去了」都不会被发现。另有 `baseExtra.penforce`（命破贯穿力）被计算器**明确忽略**（`requirements.md` §7），`baseUnmodeled` 的锐暴伤害又由 `core/modes.py:5` 硬编码 150——**同一事实两处真源** |

**T4 的修法（口径既然定了，就要让它可断言）**：

1. 在 `docs/design/calculation-rules.md` 增一节「面板口径」，逐条写明**含什么 / 不含什么**；
2. 新增「代理人 ↔ 专武」映射（`data/catalog/` 下的 **agent-weapon.json**，或给 `agents.json` 增 `signatureWeaponId`），
   来源用 Wiki 的「推荐代理人表」——本仓库已有同款抓取通道（`.github/skills/read-zzz-engine-stats/SKILL.md` 提到推荐代理人表）；
3. `buildSpec.weaponId` 必须等于该代理人的专武 id → 由测试断言；
4. `buildSpec` **不设影画字段**——口径固定为 0，字段存在即说明有人在试图把影画算进面板。

**动作**：T1~T4 全部并入 Phase 1（见 §6），因为它们是「推导引擎」的**地基**——
地基不稳时，后面所有推导结论都不可信。

### 5.2 `buildSpec` 契约：把决策参数落盘

**现状**：面板的 build 参数**全部只存在于命令行**（`calc_graduation_panel.py:555-626` 共 27 个 flag），
落盘的只有三段**自由文本**（`build.core` / `build.mainStats` / `build.subStats`）。
于是「61 份面板里只有 1 份能复算」。

**建议的新字段**（写在 `graduationPanel.buildSpec`）：

| 字段 | 类型 | 取值 | 为什么必须有 |
| --- | --- | --- | --- |
| `agentId` | str | `ep-*` | 让 `--from-strategy` 不必再传 `--agent-id` |
| `weaponId` | str | `ep-*` | 同上；音擎是面板第一大变量。**口径固定为专武 → 必须等于该代理人的专武 id，由测试断言**（依赖 T4 新增的「代理人 ↔ 专武」映射） |
| `mode` | str | `standard` / `rupture` / `fengyu` | 现在**算完就丢**，命破/锋御面板无法自证口径 |
| `rows` | str[] | `TOTAL_LABELS` 的键 | 展示行现在完全不落盘 |
| `discMain` | obj | `{disc4, disc5, disc6}` → 规则表选项 id | 主词条现在只有中文串 |
| `setGroups` | obj[] | `{kind, discId, effectId}` | 套装 id 与二件套效果 id 现在只有名字 |
| `core` | str[] | `agents.json` 的 `core[].optionId` | 现在靠 `--core1/--core2` 人工指定；但 `agents.json` 里**已经存了** `optionId`（`optionCount=2` 的角色同一个 id 占两槽） |
| `subStats` | obj | `{cr: 12, cd: 24, …}` | 现在**完全不落盘**，只有一条中文串 |
| `tier` | str | `full` / `near` | 把「满配 / 小毕业」从两个字段名变成一个结构 |
| `subStatBudget` | obj | `{total: 54, source: "gameCap"}` 或 `{total: 30, source: "community"}` | 条数门槛必须显式，并标明是**推导**还是**口径** |
| `objective` | str | 如 `crit` / `attack` / `penforce` | 主词条取舍需要一个「要什么」，否则无法自动排序 |
| `derivation` | obj[] | `{step, reason, evidence}` | **推导链**：每一步为什么这么选 |

**刻意不设的字段**（口径固定，字段存在本身就是错误信号）：

| 不设 | 原因 |
| --- | --- |
| `cinema` / `film` | 影画口径固定为 **0**。设了字段就意味着有人想把影画算进面板 |
| `inCombat` | 局内口径**不属于面板层**。局内叠加属于攻略层的文字说明 |
| `weaponPolicy` | 音擎口径固定为**专武**，只有一个合法取值，不需要可配置项——用 `weaponId` + 断言表达就够 |

**兼容性**：新增字段不破坏现有结构（旧文件没有 `buildSpec` 时行为不变）；
`--check-all` 在有 `buildSpec` 的文件上**实算比对**，没有的**降级为形状校验 + 明确 WARN**（而不是静默放过）。

### 5.3 理论计算环节清单

每一项 = 一个**可复算工具** + 一份**可展示的论证表**。这是「让不同代理人独立理解与计算」的实体。
**注意分层**：标 [面板] 的产出进 `graduationPanel`；标 [攻略] 的产出进正文 / `weapons[].note` / `cinemaPriority.note`，
**不进入面板数值**。

| 编号 | 环节 | 层 | 输入 | 算法 | 输出 | 落点 |
| --- | --- | --- | --- | --- | --- | --- |
| **D1-Wpn** | **专武 vs 其他音擎的数值差距** | [攻略] | `weapons.json`（base/substat）+ 代理人 base/core + 目标配装 | 对每把候选音擎各跑一次面板计算 → 逐行差值；**基础值走加法侧、副词条走百分比侧，必须分开算**（`build_request()` `:396-407`）。**面板本身恒取专武**，这里的对比是给读者看「换把会差多少」 | 音擎对比表（Δ攻击力 / Δ暴击率 / Δ暴伤 / Δ穿透值 / Δ冲击力 / Δ异常精通…）+ 结论 | 新脚本 `tools/*_compare.py`；结果落**攻略层**（`weapons[].note` 的数据来源），**不进 `graduationPanel.totals`** |
| **D1-Cine** | **影画的相关提升** | [攻略] | 影画条目（关键影画等级）+ 专武局内加成 + 局外面板 | **不进面板**。只算「局外面板 + 影画 N 层 → 局内实际值」的**文字结论**（如「影画 L1 +8% 暴击率 → 局内正好 100%」） | 攻略层的影画说明段 | 策略 JSON 的 `cinemaPriority.note` 已有该位；**不新增数据集**（口径固定后，面板不需要影画加成表） |
| **D1-Ben** | **词条的边际收益** | [面板] | 代理人 + 配装 + 某词条 | 对某词条加 N 条（1..上限）→ 重算面板 → 得各面板行的增量曲线 | 词条 × 档数 → Δ面板行 的收益矩阵 | 新脚本 `tools/*_benefit.py` |
| **D1-Eq** | **副词条的等效与优先级** | [面板] | D1-Ben 的曲线 | 等效：求「使目标面板行提升相同」的条数比；优先级：验证 `driveBuilds[].subPriority` 里的 `>` / `=` / `≈` 符号是否与实算一致 | 等效换算表（1 条 X ≈ N 条 Y）+ **优先级链的偏差清单** | 同上脚本（`--equivalence` / `--verify-priority`） |
| **D1-Main** | **主词条的取舍** | [面板] | 4 号位 6 选 1、5 号位 5 选 1、6 号位 6 选 1 | 遍历组合 → 对每组算面板；**主词条会挤掉对应副词条**（`MAIN_STAT_OPTION_ID_TO_EXCLUDED_SUB_STAT`，`frontend/src/constants/calculatorOptions.ts:119`），所以取舍必须与副词条预算**联动**，不能分开算 | 4/5/6 号位各自的 Top-N 与理由（不是一句「首选 X」） | 新脚本 `tools/*_compare.py`（与 D1-Wpn 同框架） |
| **D1-Set** | **套装效果取舍** | [面板] | `drive-discs.json` 的 `effect2` + `effect2Note` | 可算套装参与排序；**不可算套装（属性伤害 / 条件触发）必须显式标记**而不是当作等价 | 带「需人工判断」标记的候选表 | 同上；与 F3 联动 |
| **D1-Tier** | **满配 / 小毕业两档的门槛** | [面板] | 满配上限（54 = 6 盘 × 9 条，规则表上限）+ 边际收益曲线 | 门槛可推导：以「达到满配面板收益的 X%」为准；或保留「每盘 3 条有效词条 = 30 条」的社区口径但**标注为口径而非推导** | 每档的条数 + `source`（`derived` / `community` / `manual`） | `buildSpec.subStatBudget`；术语写进 `strategy/README.md` 与 `docs/design/calculation-rules.md` |

**目标口径的变更（A3-选 ③ 之后）**：上表的收益**一律以伤害为口径**，不再以面板行为口径。
面板口径的收益表只保留一份，用途是**解释**（「为什么这条优先」），不参与决策——
因为攻击力 / 双爆 / 穿透值 / 异常精通的收益顺序在两种口径下并不相同。

因此每个工具的依赖关系是：

```
G1 乘区总纲 → 伤害引擎 → D1-Ben 边际收益（伤害口径）
                              ├→ D1-Eq 等效与优先级
                              ├→ D1-Main 主词条取舍
                              └→ D1-Tier 两档门槛
```

**面板层与引擎层的关系**（避免滑向完整战斗模拟）：
引擎在**局外口径**（0 影画 + 专武）上求最优，与面板同一口径；
影画、局内加成、队伍增益**不进引擎**，它们是攻略层的文字。

**口径固定带来的两个简化**：

1. **D1-Cine 从「面板工具」降为「攻略文字」**——面板不需要影画加成表，也就不必新建数据集与抓取脚本；
   影画相关只保留「关键影画 + 对局内的意义」这类说明（`cinemaPriority` 已有该位）。
2. **D1-Wpn 从「面板对比」降为「攻略对比」**——面板恒取专武（可断言），音擎之间的差距是**读者的参考信息**，
   不是面板输入；但**数字仍应由工具实算**，不能继续手写在 `weapons[].stats` 里（那是 T3 之外的第二处手维护真源）。

**D1-Ben 的一条重要边界**：面板口径的收益 **≠** 伤害口径的收益。
攻击力 / 双爆 / 穿透值 / 异常精通 与伤害强相关；生命值% 对非命破角色近乎无关，
防御力% 几乎无关（除非面板模式是 rupture / fengyu）。
工具输出必须**按面板行分组**，并在文档里写明这一点——
否则「边际收益」会被误读成「伤害收益」。

### 5.4 推导链的呈现

**现状**：攻略页只给结论（`totals` + 一句 `note`），不给推导过程。
读者（以及后续维护者）无法判断「这个 30 条的分配是不是合理」。

**建议**：面板块增加 `derivation` 段（机器可读），前端渲染成「为什么这么配」：

```
面板层（0 影画 + 专武）
① 目标：局外暴击率 ≥ 72%（依据：本面板为 0 影画 + 专武口径，72% 是本面板自己的目标线）
② 主词条：4 号位暴击率 +24%（暴伤被 5 号位穿透率挤掉，暴率更早到线）
③ 副词条：暴击率 ×12、暴击伤害 ×12、攻击力% ×1、穿透值 ×5（共 30 条 = 每盘 3 条有效词条）
④ 档位门槛：小毕业线 = 满配 54 条收益的 78%，来源：community（每盘 3 条）
```

**攻略层的复杂情况另起一段**（不进面板数值，单独标注「以下为攻略补充，非面板口径」）：

```
攻略层（不参与面板计算）
⑤ 影画：关键影画 L1 暴击率 +8%（L4「焚昼孽火」提供护盾与失衡）
⑥ 专武局内：「日蚀效应」+20% 暴击率
⑦ 局内满暴率线：面板 72.2% + 专武 +20% + 影画 +8% → 局内正好 100%（按各加成互不重叠手推）
⑧ 换音擎：换成「光影刻刀」面板暴击率 -12.2%、攻击力 -119（工具实算，攻略层参考）
```

每条 `derivation` 带 `evidence`（指向本次工具的输出或底层机制系列文章），
满足「**数字必须可核对**」这条既有文档纪律。
**分层的意义**：面板层的每一条都能被 `--from-strategy` 复算；攻略层是**读者参考**，允许手推但必须标注是手推。

### 5.5 闸门升级路径

| 阶段 | 闸门 | 覆盖 |

### 8.3 底层机制理论速查（若将来做伤害引擎的准绳）

以下公式以底层机制系列 + 666bj《数据机制导论 2.0 版》交叉校对为准。
**本项目当前不实现它们**（`docs/overview/requirements.md` §3.2 的边界），此处只作 G1 的素材。

```
常规伤害 = 基础伤害区 × 增伤区 × 暴击区 × 防御区 × 抗性区 × 减易伤区 × 失衡易伤区 × 特殊乘区
贯穿伤害 = 基础伤害区 × 增伤区 × 暴击区 × 贯穿增伤区 × 抗性区 × 减易伤区 × 失衡易伤区 × 特殊乘区
异常伤害 = 基础伤害区 × 增伤区 × 异常精通区 × 防御区 × 抗性区 × 减易伤区 × 失衡易伤区
           × 伤害等级区 × 异常增伤区 × 异常暴击区
失衡累积 = 基础失衡区 × 失衡抗性区 × 失衡值提升区 × 受到失衡值提升区 × 距离衰减区
基础失衡区 = 冲击力 × 失衡倍率
```

| 乘区 | 公式 | 有效范围 |
| --- | --- | --- |
| 增伤区 | `1 + Σ增伤`（加算；**贯穿增伤 / 异常增伤 / 直接攻击增伤不属此区**） | [0, 6] |
| 暴击区 | 暴击 `1+暴击伤害`；期望 `1+暴击率×暴击伤害`；原始暴伤 100% | — |
| 防御区 | `攻击方等级基数 / (受击方有效防御 + 攻击方等级基数)` | (0, 1]，实测下限 0.0283 |
| 受击方有效防御 | `受击方防御 × (1 − 穿透率) − 穿透值` | ≥ 0 |
| 受击方防御 | `(初始防御力×(1+局外防御%) + 局外固定防御) × (1+局内防御加成% − 局内防御降低% − 无视防御%) + 局内固定防御` | — |
| 抗性区 | `1 − 受击方抗性 + 受击方抗性降低 + 攻击方无视抗性` | 弱点 +20% / 抗性 −20% |
| 减易伤区 | `1 + 受击方易伤 − 受击方减伤` | [0.2, 2] |
| 失衡易伤区 | 失衡 `1+失衡易伤`，未失衡 `1+未失衡倍率` | 默认 25% / 50% / 100% |
| 伤害等级区 | `trunc(1 + (等级−1)/59, 4)` | 1 级 = 1，60 级 = 2 |
| 异常精通区 | `异常精通 / 100` | [0, 10]（1.4 前 [0, 6]） |
| 异常增伤区 | `1 + 异常伤害提升`（属性异常 / 紊乱 / 异放 / 乱流增伤**相加**） | [0, 3] |
| 异常暴击区 | 暴击 `1+异常暴击伤害`；期望 `1+异常暴击率×异常暴击伤害` | — |
| 异常掌控区 | `异常掌控 / 100`（**向下取整**） | [0, 3] |
| 贯穿增伤区 | `1 + 贯穿增伤` | [0.2, 9] |
| 异常积蓄值 | `技能基础积蓄 × 异常掌控区 × 异常积蓄效率区 × 异常积蓄抗性区 × 距离衰减区` | — |
| 失衡等级区（紊乱） | `1 + 0.0075 × 等级` | 1 级 1.0075，60 级 1.45 |
| 等级基数 | 60+ 恒为 `794`（敌人超 60 同样 794） | — |
| 敌人基础防御 | `1 级基础防御 / 50 × 该等级的攻击方等级基数` | 小怪 36 / 精英 45~54 / 杜拉罕 58 / 首领 60 |

**局内 / 局外**：场外白值 + 场外绿值 → 进战斗合并成战斗白值（能量自动回复、攻击力、冲击力同构）。

**快照 / 实时**：攻击力、增伤、等级、穿透率、穿透值、异常精通、失衡值提升 → **积蓄时加权**；
抗性、减抗、减防、无视防御与无视抗性、失衡易伤、异常增伤、异常暴击 → **结算时实时**。
