# 待执行计划

本目录存放**尚未执行**的修缮计划：写清楚要改什么、为什么改、改哪些文件、怎么验收。

> ⚠️ **计划不描述当前状态，只描述「打算做什么」。**
> 想知道项目现在是什么样，请看 [../overview/](../overview/) 与 [../design/](../design/)；
> 想知道已经做完的事，请看 [../completeds/](../completeds/)。

## 计划的生命周期

1. **立项**：写计划 → 放进本目录 → 在 [../README.md](../README.md) 索引里登记一行。
2. **执行**：逐条做，每条做完在计划里把状态从「待办」改成「已完成」并附上验收命令的实际输出。
3. **收尾**：全部条目完成后，把文档 `git mv` 到 [../completeds/](../completeds/)，
   修正所有指向它的链接，在 [../changelog.md](../changelog.md) 记一笔。

## 计划必须写清楚的四件事

| 要素 | 要求 |
| --- | --- |
| **落点** | 具体到「文件:行」，让人能直接跳过去改 |
| **依据** | 数据结论要给出处（官方页面 URL / 抓取日期 / 参考项目文件与行号） |
| **验收** | 给可执行的命令，而不是「跑一下测试」 |
| **风险** | 动到冻结资产（例如三方对拍的参照实现夹具）时，必须写明裁决口径 |
