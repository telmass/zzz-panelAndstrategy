## 0. 这份计划是什么

上一份计划把**伤害引擎的骨架**立起来了：乘区规格、引擎实现、目标函数、边际收益、
音擎/主词条/档位门槛对比。但对照官方资料后发现，**引擎只覆盖了「常规直伤」与「异常伤害」两条路径**，
其余职业口径与参数数据都还是空的。

本计划补齐这些缺口：

```
                 ┌─ 常规直伤（已实现）
                 ├─ 异常伤害（已实现）
   伤害引擎 ──────┼─ 贯穿伤害（命破）   ← 基础属性口径没接
                 ├─ 锐化伤害（锋御）   ← 基础属性口径 + 独立暴击区 + 锐化增伤区没接
                 └─ 风属性（乱流）     ← 未实现
```

外加**三份参数数据集**（技能倍率、敌方参数、锐暴/转模），它们是「用引擎比较两套配装」
真正需要的东西。

## 2. 裁决项（Phase 0：先定口径，再动代码）

### D-2 · 职业口径进不进「伤害目标函数」？

| 选项 | 内容 | 代价 |
| --- | --- | --- |
| ① **进**（推荐） | 引擎按代理人的 `panelMode` 选路径：标准→常规直伤、命破→贯穿、锋御→锐化、异常→异常伤害 | 需要给引擎补「基础属性取哪一项」的口径 |
| ② 不进 | 目标函数只用常规直伤，命破/锋御的角色**不参与**配装比较 | 命破/锋御角色无法用引擎比较配装——等于放弃一半角色 |
| ③ 分期 | 本期只做常规 + 异常，命破/锋御留到下期 | 同 ① 的问题，只是延后 |

**建议**：选 ①。理由：口径选择是**引擎内部**的事（同一个角色换音擎/换主词条时路径不变），
不进目标函数只是「暂时不给某些角色打分」，而目标函数的价值恰恰在比较。

### D-3 · 锐暴伤害与转模比例放哪？

| 选项 | 内容 | 代价 |
| --- | --- | --- |
| ① **进代理人预设**（推荐） | `agents.json` 增 `fengyuBlastDamage` / `fengyuCritFromCd`；`core/modes.py` 读预设，不再硬编码 | 要改预设 schema + 校验 + 61 份预设（多数填默认值） |
| ② 进规则表 | 当作「全体锋御共用」的一条规则 | 与官方「逐代理人而定」冲突，未来要推翻 |
| ③ 继续硬编码 | 不动 | 与官方口径冲突，且永远补不上加成来源 |

**建议**：选 ①。

### D-4 · 撕裂暴击（`lacerationCrit`）本期做不做？

参考实现的锋御有**三种**暴击模式：`nonCrit` / `sharpCrit` / `lacerationCrit`。
本项目目前只有「暴击一次 / 暴击两次」的平方项结构。

| 选项 | 内容 | 代价 |
| --- | --- | --- |
| ① **只登记不实现**（推荐） | 缺触发条件与倍率数据，猜不得 | 锋御的撕裂收益无法评估 |
| ② 实现 | 需要从参考实现/官方补齐触发条件与倍率 | 要新增数据来源，且规则可能随版本变 |

**建议**：选 ①，先把口径写进规格（见附录），等有官方出处再实现。

### D-5 · 乱流与耀变本期做不做？

- **乱流**：公式与倍率表已齐（见附录），可实现，但需要**异常积蓄过程**（时间项 `T` 的推进）——
  这与「不做完整战斗模拟」的边界冲突。
- **耀变**：参考实现把它建成**独立的队伍评分**，不是伤害事件；要实现等于新建一套评分模型。

**建议**：选「**本期都不实现**」，但把口径与公式**完整写进规格**（已做一部分），
留作独立计划。理由：两者都属于「异常结算过程」，与本计划的核心（职业直伤口径 + 参数数据集）不同源。

## 3. 线一：职业口径（锋御 / 命破）

### A1〔P1〕锐化增伤区——独立乘区

**官方口径**：锋御有「**锐化增伤**」，是**独立乘区**，与常规增伤区**独立计算**（互不稀释），
量级约 10%；与命破的「贯穿增伤区」同理。

**动作**：

1. `core/damage/zones.py` 新增 `sharpen_damage_bonus_zone(total)` = `1 + Σ`（有效范围待定，官方只给了量级）。
2. `core/damage/engine.py` 的 fengyu 分支接入该乘区。
3. 契约：与常规增伤区**互不稀释**（同 C6 的写法）。

**缺什么**：锐化增伤的**来源**（驱动盘 4 件套 / 音擎 / 影画 / 额外能力）——本项目没有这些数据集。
**因此本期只做机制，不做数据**：乘区恒为 `1 + 0`，等来源数据到位再填。

### A2〔P1〕锋御：基础属性 + 暴击区接入目标函数

**官方口径**：
- 锋御的直伤统称「**锐化伤害**」，用**防御力**作为基础属性（把常规公式里的攻击力换成防御力）。
- 锋御的**暴击不用暴击伤害结算，而用「锐暴伤害」**；**暴击率可以超过 100%**，
  超出的部分**再判定一次锐暴**——于是锐暴伤害在公式里是**平方项**。
- 锋御的暴击率**上限 200%**。
- 锋御的**音擎基础属性无一例外是基础防御力**。
- 锋御的**异常伤害仍用攻击力**。

**动作**：

1. `core/damage/engine.py` 的 `DamagePath` 增 `"fengyu"`：
   - 基础伤害区 = 倍率 × **防御力**（取面板 `def`）
   - 暴击区 = `fengyu_crit_zone(面板 actual_cr, 锐暴伤害)`（函数已实现，见上一期契约 C32）
   - 增伤区之后接 **锐化增伤区**（A1）
2. `services/damage_service.py` 的 `score_build` 按代理人的 `panelMode` 选路径：
   `standard`→常规、`rupture`→贯穿、`fengyu`→锐化、异常定位→异常伤害。
3. 面板的 `actual_cr` 已经是「暴击率 + 初始暴伤 × 转模比例」的结果（`core/modes.py`），
   引擎**直接用面板值**当暴击率即可，**不要在引擎里再转一次模**。

**验收**：给克拉蕾造一个 buildSpec，`score_build` 的结果要满足
「锋御暴击区 = 2.5（暴击率 ≤ 100%）或 k×[1+(c−1)k]（> 100%）」，且防御力进基础伤害区。

### A3〔P1〕撕裂暴击——只登记（见 D-4）

规格已补：锋御有 `nonCrit` / `sharpCrit` / `lacerationCrit` 三种模式，本项目只建模前两者。
**动作**：在 `core/damage/engine.py` 的 fengyu 分支留注释指向该缺口；不实现。

### A4〔P1〕命破：贯穿力口径接入

**官方口径**：
- 命破的直伤用**贯穿力**作基础属性；**贯穿力 = 0.3 × 攻击力 + 0.1 × 生命值上限**——
  **所有命破代理人统一**这个比例（游戏内文案各写各的，实际结算一致）。
- 命破的直伤**无视 100% 防御**：防御区乘数恒为 **1.000**。
- 命破的**异常伤害仍用攻击力**。

**动作**：
1. `engine.py` 的 piercing 分支：基础伤害区 = 倍率 × **贯穿力**（取面板 `penforce`）。
2. 面板已有 `penforce` 行（`core/modes.py` 的 rupture 模式）✓ → 引擎直接取。
3. 契约：贯穿路径的防御区乘数恒为 1（把「跳过防御区」显式成「防御区 = 1」，
   便于白盒显示，也与官方措辞一致）。

### A5〔P2〕锋御 / 命破的「音擎基础属性」口径

**现状**：本项目的音擎预设已有 `base.kind`（`atk` / `def`）✓，且 `core/panel.py` 只在
`baseKind == "def"` 时把基础防御力计入防御力 ✓。
**缺口**：**锋御的角色拿攻类音擎时，基础攻击不计入**（锋御音擎全是防类）——
  这由**预设数据**保证（抓取脚本给的是防类音擎），不需要新代码。
**动作**：写进规格的「口径」节，作为**数据前提**说明，不改代码。

## 4. 线二：参数数据集

### B1〔P1〕锐暴伤害进代理人预设

### B2〔P1〕转模比例进代理人预设

**现状**：硬编码 `FENGYU_CRIT_FROM_CD = 0.35`。
**官方口径**：官方说「大多也应该是 0.35，**除非有什么特殊需要**」——逐代理人而定。

**动作**：`agents.json` 增 `fengyuCritFromCd`（默认 0.35）；`core/modes.py` 读预设。

### B3〔P2〕技能倍率数据集

**缺口**：引擎的「基础伤害区 = 倍率 × 属性」里，**倍率**目前只能传 1
（`score_build(multiplier=1)`）。要比较真实配装，需要**每个代理人每个技能的倍率**。

**动作**：
1. 新数据集 `data/catalog/skill-multipliers*.json`：`{agentId: {skillId: [lvl1..lvl16]}}`。
2. 来源：参考实现有 `zzz_calculator:data/agent_skills.json`（448KB，含 16 级倍率）——**但那是别人的数据**，
   需核对口径（倍率是「伤害倍率」还是「失衡倍率」）后再用。
3. 在 `score_build` 支持 `skill_id` + `level` → 自动取倍率。

### B4〔P2〕敌方参数数据集扩展

**现状**：只有标准目标「60 级以上首领」（`core/damage/targets.py`）。
**缺口**：普通 / 精英 / 首领三档的基础防御区间（36~46 / 45~54 / 60）、
逐属性弱点 / 抗性分布（法厄同图鉴）、失衡易伤倍率（25% / 50% / 100%）。

**动作**：
1. `core/damage/targets.py` 增三档目标 + 逐属性抗性表（来源：法厄同图鉴 / 官方合集）。
2. **区分「有官方出处」与「取默认值」**——每条都记出处。
3. 引擎支持选目标（现在只有默认）。

## 5. 线三：风属性与耀变（本期只登记，见 D-5）

### C1〔P2〕乱流

口径**已完整写进规格**（`docs/design/damage-formulas.md` §3.13）：
公式、按基底异常分的固定倍率表、触发关系、事件存储约束。

**为什么本期不做**：乱流的倍率含**时间项** `floor(T) × k`，
`T` 是「非风基底异常的剩余时间」——要算它就得推进异常积蓄过程，
这与本项目「不做完整战斗模拟」的边界冲突（`docs/overview/requirements.md` §3.2）。

### C2〔P2〕耀变

参考实现把耀变建成**独立的队伍异常评分**，不是伤害事件（有专用异化公式、
不读队友异化乘区、流明直伤事件不得进入该评分）。要实现等于**新建一套评分模型**，
且它的输入（队友攻击力、经验占比、异化规则）都不在本项目的数据集里。

## 6. 线四：验证

### D1〔P1〕朴素对照扩到新路径

`backend/tests/naive_reference.py` 现在只覆盖常规 / 贯穿 / 异常三条路径。
**动作**：补锋御路径（防御力基础 + 平方项暴击区 + 锐化增伤区）的朴素重写，
并把命破路径的**基础属性**也纳入对照。

### D2〔P1〕fuzz 扩到新路径

**动作**：随机用例覆盖 fengyu / rupture 路径；断言乘区不越界、
输出有限、与朴素实现在同输入上一致。

### D3〔P1〕契约扩充

- 新增 **C33** 锐化增伤区与常规增伤区互不稀释
- 新增 **C34** 锋御暴击区在目标函数里被真正使用（`score_build` 走 fengyu 路径）
- 新增 **C35** 命破贯穿路径的防御区乘数恒为 1
- 新增 **C36** 锋御路径的基础伤害区用**防御力**而非攻击力

### D4〔P2〕面板侧不动

**纪律**：本计划**不改面板口径**。面板永远是「0 影画 + 专武的局外面板」；
职业口径只进**伤害引擎**与**目标函数**。面板行不新增（新增行会破坏三方对拍）。

## 9. 附录：口径与数据来源

### 9.1 锋御

| 项 | 官方口径 | 来源 |
| --- | --- | --- |
| 锐化伤害 | 用**防御力**作基础属性，乘区与常规相同 | [锋御第十一期](https://www.miyoushe.com/zzz/article/78724467) |
| 锐化增伤 | **独立乘区**，约 10%，与常规增伤独立 | 同上 |
| 锐暴伤害 | 暴击用锐暴伤害结算；**暴击率可超 100%**，超出部分再判一次；平方项 | 同上 |
| 暴击率上限 | **200%** | 参考实现 `core/sharpDamage.js` `critRateCapPct` |
| 转模比例 | 暴击伤害 → 暴击率，**逐角色**（克拉蕾 0.35） | 参考实现 `initialCritDmgToCritRateRatio` |
| 暴击模式 | `nonCrit` / `sharpCrit` / `lacerationCrit` | 参考实现 `SHARP_CRIT_MODES` |
| 能量 | 叫「锐能」，**不吃驱动盘 6 号位能量自动回复** | 锋御第十一期 |
| 能量基准 | 非命破 1.2、命破 2（4 星真斗 0）、锋御（克拉蕾）1.5 | 锋御第十一期 |
| 音擎 | 锋御音擎基础属性**无一例外**是基础防御力 | 锋御第十一期 |
